Boris (Anthropic) gyakorlati Claude Code tippjei a terminálban

A Claude Code megalkotójának bevált módszerei a konfigurációtól a headless automatizálásig.

Boris Cherny, az Anthropic fejlesztője és a Claude Code megalkotója egy 28 perces előadásban mutatta be az ágens leghatékonyabb gyakorlati használatát. A prezentáció a mindennapi fejlesztői munkafolyamatokra fókuszál: beállításokra, promptolási mintákra, a kontextushierarchiára, a terminál gyorsbillentyűire és a headless automatizációra. Ez az összefoglaló a konkrét parancsokat, promptokat és bevált módszereket gyűjti egybe mindazoknak, akik maximális hatékonysággal szeretnék használni a Claude Code-ot.

A fenti videó a cikk másfél perces magyar összefoglalója. A teljes anyag ez: Boris előadása, huszonnyolc perc, angolul.

Környezet és beállítások

A Claude Code nem kiegészítő eszköz, hanem autonóm ágens, amely komplett funkciókat épít, fájlokat kezel és hibákat javít bármely editor (VS Code, Xcode, JetBrains, Vim, Emacs) mellett, lokálisan vagy SSH/tmux alatt.

Telepítés Node.js környezetben:
```bash
npm install -g @anthropic-ai/claude-code
```

Kezdeti beállítási parancsok:
- `/terminal-setup`: bekapcsolja a Shift+Enter kombinációt az új sorokhoz.
- `/theme`: sötét, világos vagy daltonizált téma beállítása.
- `/install-github-app`: telepíti a GitHub appot (@claude említéshez issue-kban és PR-ekben).
- `/allowed-tools`: engedélyezett eszközök listája a felesleges jóváhagyások elkerülésére.
- `/config`: értesítések bekapcsolása.
- macOS Diktálás: Boris nem gépeli a hosszú promptokat; kétszer leüti a diktálás billentyűt, és élőszóban diktálja le a részletes feladatot.

Első szint: Kérdezz a kódbázisról

Tip #1: Használd a kódbázis Q&A-t a kezdeti lépésekhez.
Új fejlesztők betanításakor a kérdésfeltevés a legjobb kiindulópont. Az Anthropicnál a mérnökök onboarding ideje 2-3 hétről 2-3 napra csökkent, mert az első naptól kezdve a Claude-ot kérdezik a kódról.
- Zero setup és zero indexing: nincs előzetes indexelés, azonnal használható.
- Helyi adatkezelés: a forráskód helyben marad, nem töltődik fel adatbázisba, és nem tanítanak rajta generatív modelleket.

Tip #2: Gyakorold a promptolást a határok kiismerésére.
A Q&A során megismered, mit old meg a modell egyetlen utasításból, és mikor kell lépésről lépésre vezetni az interaktív REPL felületen.

Konkrét prompt-példák:
- `How is @RoutingController.py used?` (Feltérképezi a példányosításokat és a hívási környezetet, a dokumentációkhoz hasonló mélységben).
- `How do I make a new @app/services/ValidationTemplateFactory?`
- `Why does recoverFromException take so many arguments? Look through git history to answer` (A git log és a commitok alapján önállóan összefoglalja a paraméterek történetét).
- `Why did we fix issue #18303 by adding the if/else in @src/login.ts API?`
- `In which version did we release the new @api/ext/PreHooks.php API?`
- `Look at PR #9383, then carefully verify which app versions were impacted`
- `What did I ship last week?` (Boris minden hétfői standup előtt ezt futtatja a saját commitjai kigyűjtésére).

Második szint: Kódszerkesztés és munkafolyamatok

A beépített eszközkészlet (bash, fájlkeresés, fájllistázás, fájlírás/olvasás, webes lekérés/keresés, TODOs, alágensek) segítségével a modell önállóan szerkeszti a kódot.

Tip #3: Tanítsd meg a Claude-ot a saját eszközeid használatára.
- Egyedi CLI eszközök: `Use the barley CLI to check for error logs in the last training run. Use --help to check how to use it.`
- MCP integráció: `$ claude mcp add barleyserver -- node myserver`, majd: `Use the barley MCP server to check for error logs in the last training run.`

Tip #4: Válaszd a feladathoz illő munkafolyamatot.
1. Feltárás, tervezés, jóváhagyás:
`Figure out the root cause for issue #983, then propose a few fixes. Let me choose an approach before you code. ultrathink.` (vagy: `Propose a few fixes for issue #8732, then implement the one I pick.`, `think hard.`)
2. Tesztvezérelt ciklus (TDD):
`Write tests for @utils/markdown.ts to make sure links render properly (note the tests won't pass yet, since links aren't yet implemented). Then commit. Then update the code to make the tests pass.`
3. Vizuális visszacsatolási hurok:
`Implement [mock.png]. Then screenshot it with Puppeteer and iterate till it looks like the mock.` (A tesztekkel vagy Puppeteer képernyőképekkel támogatott iteráció 2-3 lépésben szinte tökéletes eredményt ad).

Gyakori kombinált parancsok:
- `commit, push, pr`: a commit stílusának felmérése, branch készítés, commitolás, push és PR nyitás egyben.
- `Use 3 parallel agents to brainstorm ideas for how to clean up @services/aggregator/feedservice.cpp.`: párhuzamos ágensek indítása.

Harmadik szint: Kontextuskezelés és CLAUDE.md hierarchia

Tip #5: Minél több a releváns kontextus, annál jobb a végeredmény.

Tip #6: Finomhangold a kontextust, és tartsd tömören.
A túl hosszú CLAUDE.md feleslegesen terheli a kontextusablakot. Csak a legfontosabb bash parancsokat, kódolási konvenciókat és architektúrális döntéseket rögzítsd.

A négyrétegű konfigurációs és memóriahierarchia:
1. Enterprise policy: `/Library/Application Support/ClaudeCode/CLAUDE.md` és `policies.json` (központi jóváhagyások és tiltások).
2. Global (felhasználói): `~/.claude/CLAUDE.md`, egyéni parancsok (`~/.claude/commands/foo.md` -> `/user:foo`), `~/.claude/settings.json`.
3. Project shared (gitbe mentve): `CLAUDE.md`, közös parancsok (`.claude/commands/foo.md` -> `/project:foo`), `.claude/settings.json`, `.mcp.json`.
4. Project local (egyéni, nincs gitben): `CLAUDE.local.md`, `.claude/settings.local.json`.

Az almappák `CLAUDE.md` fájljai csak akkor töltődnek be automatikusan, amikor a Claude az adott mappában dolgozik. Az Anthropicnál a `.claude/commands/label-github-issues.md` parancsot GitHub Actions futtatja, míg a közös `.mcp.json` a Puppeteer MCP elérését biztosítja a csapatnak.

Memóriakezelési parancsok:
- `/memory`: betöltött memóriafájlok megtekintése és szerkesztése.
- `#`: gyorsbillentyű új szabály hozzáadására a kiválasztott memóriafájlba.

Tip #7: Állítsd be a CLAUDE.md-t, MCP szervereket és parancsokat, majd mentsd a gitbe a csapatszintű előnyökért.

Gyorsbillentyűk és terminál-trükkök

  • `Shift + Tab`: automatikus szerkesztés-elfogadás bekapcsolása (a kódszerkesztések megerősítés nélkül futnak, a bash parancsok továbbra is jóváhagyást kérnek).
  • `#`: memóriabeszúrás a `CLAUDE.md`-be.
  • `!`: közvetlen bash mód (a parancs és kimenete bekerül a következő kontextusba).
  • `@`: fájlok vagy könyvtárak behúzása a kontextusba.
  • `Esc`: megszakítás a munkamenet sérülése nélkül.
  • Dupla `Esc`: visszalépés az előzményekben.
  • `--resume` vagy `--continue`: előző munkamenet folytatása a parancssorból.
  • `Ctrl + R`: teljes, részletes kimenet megjelenítése.

Automatizálás: Claude Code mint Unix segédprogram

A `-p` (print) kapcsolóval a Claude Code beilleszthető a standard Unix adatfolyamokba (pipe in, pipe out):
```bash
claude -p "what did you just do?" --output-format=json | jq '.result'
git status | claude -p "what are my changes?" --output-format=json | jq '.result'
```
Ez a megoldás közvetlenül alkalmazható CI/CD scriptekben, incidenskezelésben, valamint GCP logok vagy Sentry hibák elemzésében.

Párhuzamosítás és multi-Claude stratégiák

A power userek több párhuzamos Claude futtatásához az alábbi technikákat alkalmazzák:
1. Több terminálfül a repó külön példányaival.
2. Egyetlen repó Git worktree-kkel izolálva.
3. Távoli SSH kapcsolatok Tmux munkamenetekkel.
4. Párhuzamos GitHub Actions jobok.

Kérdezz-felelek tanulságok

  • Biztonságos bash: Statikus kódanalízis és többszintű jogosultságkezelés határozza meg az automatikusan futtatható és az engedélyköteles parancsokat.
  • Multimodalitás: Képek drag-and-drop behúzással, vágólapról beillesztve vagy fájlelérési úttal is átadhatók a terminálban UI mockupok megvalósításához.
  • Miért CLI és nem IDE?: A sokféle belső editor (VS Code, Zed, Xcode, Vim, Emacs) miatt a terminál az egyetlen univerzális felület. Emellett a modellek gyors fejlődése feleslegessé teheti a vastag IDE felületekre fordított fejlesztést.
  • Belső használat: Az Anthropic technikai munkatársainak 80%-a napi szinten használja az eszközt, beleértve a kutatókat is, akik Jupyter notebookokat szerkesztenek vele.

Tanulságok ügynök-flották és ütemezett automatizációk üzemeltetéséhez

Ha valaki ügynök-flottát üzemeltet ütemezett feladatokkal és projekt-utasításfájlokkal, az alábbi szempontokat érdemes mérlegelnie a bemutatott gyakorlatokból:

Ami közvetlenül alkalmazható autonóm ügynököknél:
- Kontextus-fegyelem: A gyökér utasításfájl (CLAUDE.md) karcsún tartása, az összetett instrukciók specializált modulokba és almappákba szervezése megvédi a kontextusablakot.
- Zárt ellenőrzési ciklusok: Az autonóm ügynökök promptjaiba épített kötelező teszt- és lintellenőrzési lépések garantálják a minőséget.
- Headless automatizáció (`-p` mód): Az ütemezett cron feladatok, hibaelemzések és standup összefoglalók közvetlenül építhetnek a standard ki- és bemenetekre.
- Git worktree izoláció: Párhuzamosan futó ügynököknél a fájlütközések elkerülésének legbiztosabb eszköze.

Ami kevésbé működik teljesen autonóm működésben:
- Interaktív terminál billentyűk: A `Shift+Tab` és `Esc` gyorsbillentyűk emberi REPL használatra készültek; az autonóm háttérfolyamatokban strukturált hibakezelés és naplózás váltja ki őket.
- Kötetlen commit és PR parancsok: Az autonóm feladatvégzés során a módosításokat szigorúbb ellenőrző kapukhoz és külön review ágakhoz érdemes kötni a közvetlen commit/push helyett.
- Indexelés nélküli forráskód-bejárás: Nagyobb méretű kódbázisok és komplex dokumentációk esetén az autonóm ügynököknek célzott keresőeszközökre és specializált modulokra van szükségük a hatékony tájékozódáshoz.
